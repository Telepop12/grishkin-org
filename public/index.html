принципы

Инженерные правила лаборатории

Confirmation pattern

Агент предлагает — человек решает. Любое изменение состояния требует явного подтверждения. Бот, который отказался заблокировать Red Team без «ДА», — не баг, а фича.

Из справки живого агента: «❌ Не могу без твоего подтверждения: перезапускать сервисы, менять конфигурацию, удалять данные».

Tool-use loop

Агент не «отвечает на промпт», а работает с целью: сам вызывает инструменты, читает результаты и останавливается, когда задача решена.

Заземление на данных

Ответы строятся на реальных источниках — SIEM, метрики, витрины DWH — а не на «памяти» модели. Меньше уверенных галлюцинаций.

Измеримость

Каждый агент — наблюдаемый объект: токены, стоимость задачи, экономия против человека. ROI — на дашборде, а не в презентации.

проекты

Хронология этапов

  • AI-SOC: L1–L3 + SOAR + CTI этапы 3–6

    Триаж, расследование и реагирование с confirmation pattern. Кейс: бот отказался блокировать «атакующего» без подтверждения — и оказался прав.

  • AD Audit Agent done

    Аудит Active Directory: от учётки уволенного сотрудника, которую «забыли», до Kerberoastable-сервисов.

  • Purple Team Agent done

    Учебные атаки Red Team против собственного SOC: измеренное покрытие детектирования вместо ощущения защищённости.

  • Egress + Insider Watch (UBA) done

    Контроль утечек и поведенческая аналитика: AI слышит, как сотрудник «уходит», раньше HR.

  • CISO Daily Brief — капстоун CTEM 15.05.2026

    Этап 7: шесть AI-специалистов + оркестратор синтезируют домены безопасности в один утренний отчёт с дельтой, топ-3 рисками и action items. «Пять слоёв защиты, пять ролей AI».

  • E2E attack chains 21.05.2026

    Этап 8b: три сквозные атаки под ключ (Lateral PtH→DC, Insider mass-read→DNS exfil, SQL TDS→1С) и 10 новых правил Wazuh в четыре слоя детекции — проверка, что SOC видит всю цепочку, а не отдельные события.

  • Data Platform + Bizbot done

    Нечитаемая база 1С превращается в DWH и «совет директоров» из AI-агентов в Telegram. Open source, один сервер, один вечер на сборку.

  • Agent Observability & FinOps in dev

    Чтобы «взвесить» агентов, все они сведены на единый shim. Токены, латентность, cost per ticket «агент vs человек», экономия человеко-часов и ROI — в Grafana.

  • AI для поддержки 1С next

    Три столпа: поддержка пользователей, разработка, администрирование. Стратегия готова, пилот — после Observability.

Web-доступ к лаборатории

Следующая фаза — превратить витрину в сервис: показать лабу вживую, не открывая периметр.

  • Живые витрины: публичные read-only дашборды Grafana (статусы агентов, метрики, ROI)
  • Демо-диалог с агентом на изолированных данных — с тем самым confirmation pattern
  • Каталог сценариев: что агенты уже умеют, с записями реальных кейсов
  • Доступ по приглашению для коллег и работодателей: песочница с гидом

Принцип периметра: лаборатория — security-полигон, поэтому доступ проектируется по её же правилам: минимум привилегий, read-only по умолчанию, любое действие — через подтверждение.
